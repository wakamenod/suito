* Suito
** 全体の構成
リポジトリは3本立て。

| ディレクトリ | 中身 |
|--------------+------|
| =mobile/=    | 本体の Flutter アプリ (iOS / Android) |
| =web/=       | Google Play Store の「データ削除ポリシー対応」用の極小 Flutter web アプリ ([[https://web.suito.wakamenod.com][アカウント削除ページ]]) |
| =supabase/=  | Supabase CLI 管理下のマイグレーション・Edge Function・pgTAP テスト |

バックエンドは Supabase (Auth + Postgres + RLS + pg_cron + Edge Functions) に全面移行済み。
Flutter からは =supabase_flutter= で PostgREST / RPC を直接叩いており、間に API サーバーはない。

移行の背景・フェーズ分けは [[file:docs/SUPABASE_MIGRATION.md][docs/SUPABASE_MIGRATION.md]] を参照。

*** Supabase 側の構成
- スキーマ・RLS・関数・cron はすべて =supabase/migrations/= のマイグレーション
  (=0001_extensions= 〜 =0005_cron=)
- テナント分離は RLS。全テーブルに =user_id = auth.uid()= のポリシーを張り、
  アプリ側の =WHERE uid = ?= を置き換えている
- 定期取引エンジンは =enqueue_transaction_schedules()= と
  =create_transactions_from_queue()= (どちらも =SECURITY DEFINER=) を =pg_cron= で毎時実行
- チャートの集計は =column_chart_data()= / =pie_chart_data()= / =transaction_months()= の RPC。
  月軸のパディングと取引一覧のマージだけ Dart 側に置いている
- アカウント削除は Edge Function =delete-account=。呼び出し元の JWT を検証し、
  自分の =user.id= 以外は削除できない。各テーブルの =auth.users= への FK が
  =ON DELETE CASCADE= なので、Auth ユーザーを消せば全データが消える
- Free プランは7日間アクセスが無いと自動 Pause されるため、
  =.github/workflows/supabase-keep-alive.yml= が1日1回 REST API を叩いている

** 旧 Go バックエンドについて
echo + gorm + MySQL + Firebase Auth + gocron で自前実装していた API サーバーは、
Supabase 移行にともないこのリポジトリから撤去した。
実装はポートフォリオとして履歴ごと別リポジトリ (=suito-go-backend=) に切り出してある。

当時試していたこと:
- Webフレームワークは [[https://github.com/labstack/echo][echo]] を使用
- ORMは [[https://github.com/go-gorm/gorm][gorm]] を使用
- 簡単な3層レイヤーを導入
- [[https://github.com/swaggo/swag][swag]] を使ったSwaggerドキュメント生成
- firebase認証
  - Middlewareでクライアントから送られたIdTokenを認証
- 独自エラー定義
- [[https://github.com/matryer/moq][moq]] を使ったモック生成
- [[https://github.com/go-co-op/gocron][gocron]] による定期処理の実装

** シークレットスキャン (gitleaks)
コミット・CI の両方で [[https://github.com/gitleaks/gitleaks][gitleaks]] を使い、認証情報の混入を防いでいる。

- 設定は =.gitleaks.toml=。デフォルトルールに加え、Supabase ローカルスタックの
  デモ用キー (=iss: supabase-demo= の JWT) や =Podfile.lock= のチェックサムなどの
  誤検知を allowlist している
- CI は =.github/workflows/gitleaks.yml= が PR と main への push で全履歴を走査する
- ローカルでは pre-commit フックでステージ済みの差分を検査する。初回のみ以下を実行:

#+begin_src sh
brew install gitleaks
just install-hooks   # git config core.hooksPath .githooks
#+end_src

- 手動実行:
  - =just scan-secrets= … git 履歴全体 (CI と同じ検査)
  - =just scan-secrets-dir= … 作業ツリー全体 (git 管理外のファイルも含む)
  - =just scan-secrets-staged= … ステージ済みの差分のみ
- 誤検知は =.gitleaks.toml= に allowlist を足すか、該当行に =gitleaks:allow= を書く。
  フックを飛ばしたいときは =git commit --no-verify=
